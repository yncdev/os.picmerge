# Pic Merge — Chrome 확장 프로그램

여러 이미지와 PDF를 하나로 합쳐 PNG나 PDF로 저장하고 공유합니다. 모든 처리는 이 PC 안에서만 하며, 네트워크를 쓰지 않고 권한도 요청하지 않습니다.

## 설치 (압축 해제된 확장 로드)

1. Chrome 주소창에 `chrome://extensions`를 엽니다.
2. 오른쪽 위 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**를 누르고 이 `chromePlugin` 폴더를 고릅니다.
4. 도구 모음의 Pic Merge 아이콘을 누르면 새 탭에서 앱이 열립니다.

Chrome 116 이상이 필요합니다.

## 할 수 있는 것

- JPEG, PNG, WebP, PDF를 2~30개 담기 (파일 선택, 끌어다 놓기). PDF는 페이지마다 1개로 펼칩니다.
- 끌어서 순서 바꾸기, 항목별 영역 자르기, 항목 삭제
- 출력 설정
  - 용지: A4(기본), A3, A5, B4, B5, Letter, Legal, 원본 크기
  - 용지 방향: 세로(기본), 가로
  - 용지당 이미지 수: 1(기본), 2, 3, 4, 6, 8, 9
  - 이미지 크기: 100%(기본), 50%, 30%. 칸에 맞춘 크기의 가로·세로 비율입니다. 50%면 넓이는 25%입니다.
  - 여백: 0%, 3%, 5%(기본), 10%. 페이지 둘레의 흰 여백이고, 칸 사이 간격은 그 0.8배입니다.
  - 색상: 컬러(기본), 흑백
  - '원본 크기'를 고르면 용지 방향, 용지당 이미지 수, 이미지 크기는 쓰지 않습니다. 여백은 씁니다.
- 미리보기: 페이지를 용지 모양으로 그려 옆으로 넘겨 봅니다. 칸 배치, 이미지 크기, 여백을 실제 결과와 같은 계산으로 보여주고, 구분선은 그리지 않습니다.
- 저장 폴더 바꾸기: 기본은 브라우저의 다운로드 폴더입니다. 하단의 '변경'에서 다른 폴더를 고르면 그 폴더에 저장하고, '기본 폴더 쓰기'로 되돌립니다. 고른 폴더는 기억하며, 브라우저를 다시 열면 저장을 누를 때 Chrome이 권한을 다시 묻습니다. 권한을 거절했거나 폴더가 지워졌으면 다시 고르게 합니다. Chrome은 다운로드 폴더 자체와 시스템 폴더를 고르지 못하게 막습니다.
- 공유: OS 공유 창, 이미지 복사(PNG), 메일 작성, 다운로드
- 최근 기록 50건과 최근 30일 성공률
- 화면 문구는 브라우저 언어를 따릅니다: 한국어, English, 日本語, 简体中文, 繁體中文, Español, Français, Deutsch, Português(브라질, 포르투갈), Русский, Tiếng Việt, Bahasa Indonesia, ไทย. 그 밖의 언어는 English입니다. 번역은 AI가 했고 원어민 검수 전입니다.

## 결과 파일

항목을 '용지당 이미지 수'만큼 묶어 용지 한 장에 넣습니다. 페이지 네 변에 용지 짧은 변의 P%(여백 설정, 기본 5%)를 흰 여백으로 두고, 칸은 그 안쪽에서 나눕니다. 칸 사이 간격은 여백의 0.8배로 기본은 4%입니다. 여기까지는 PNG와 PDF가 같습니다.

**PNG**는 페이지가 없는 형식이라 용지를 한 파일 안에 이어 붙입니다.

- 세로 용지는 옆으로, 가로 용지는 위아래로 잇습니다.
- 이미지 사이와 페이지 사이에 옅은 회색(#D0D0D0) 구분선을 넣습니다. 두께는 짧은 변의 0.3%이고 최소 2px입니다.
- 전체가 2,400만 픽셀을 넘으면 같은 비율로 줄입니다. 페이지가 많을수록 페이지당 해상도가 낮아지므로, 인쇄할 때는 PDF가 낫습니다.
- '원본 크기'는 이미지 비율로 방향을 정하고, 이미지마다 공통 변의 P%를 흰 여백으로 둡니다. 여백은 불투명한 흰색이고 이미지 안의 투명 픽셀은 그대로 둡니다.
- 여백이 0%면 이미지 사이가 구분선 하나만큼만 벌어지고 선이 그 자리를 채웁니다.

**PDF**는 용지 한 장이 한 페이지이고 구분선이 없습니다. 여백이 0%면 칸이 맞닿습니다. '원본 크기'는 이미지마다 한 페이지로, 이미지 짧은 변의 P%를 네 변에 흰 여백으로 두고 긴 변을 297mm에 맞춥니다.

파일 이름은 `YYYYMMDDHHMI_연번.확장자`입니다 (예: `202610301536_1.png`). 같은 분에 또 저장하면 `_2`가 되고, PNG와 PDF는 연번을 따로 셉니다. 고른 폴더에서는 실제 파일을 보고 연번을 정합니다. 기본 폴더는 안을 볼 수 없어 최근 기록의 이름으로 정하고, 그래도 겹치면 브라우저가 번호를 더 붙입니다.

결과 파일은 20MB를 넘지 않습니다. 넘을 것 같으면 자동으로 줄이고, 그래도 넘으면 오류로 안내합니다.

## 할 수 없는 것

- 카메라 촬영
- HEIC/HEIF 입력 (Chrome이 풀 수 없어 제외 안내합니다)
- 암호가 걸린 PDF 입력 (제외 안내합니다)
- 카카오톡·문자로 바로 보내기. OS 공유 창에 그 앱이 있으면 고를 수 있고, PNG는 복사해서 PC 카카오톡에 붙여넣을 수 있습니다.
- 메일에 파일 자동 첨부. '메일 작성'은 파일을 내려받고 메일 앱을 열어 주며, 첨부는 직접 합니다.
- 배치 방향 직접 선택 (자동으로 정합니다)
- 앱 안에서 언어 고르기 (브라우저 언어를 따릅니다)

## 개발

단위 테스트는 의존성 없이 돕니다.

```
cd chromePlugin
node --test
```

실제 Chrome으로 하는 E2E는 저장소 최상위에서 돌립니다. 확장 폴더 밖에 있어 배포물에 들어가지 않고, 의존성이 없습니다 (Node 22.2 이상).

```
node tool/chrome_e2e/run.mjs           # 전체 (언어 15개, 잡음 이미지 재인코딩 포함)
node tool/chrome_e2e/run.mjs --quick   # 한국어와 English만
```

- 임시 프로필로 Chrome을 따로 띄우고, 끝나면 그 프로세스만 닫습니다. 사용자의 Chrome과 프로필은 건드리지 않습니다.
- 정식 Chrome은 137부터 `--load-extension`을 무시합니다. 그래서 `--remote-debugging-pipe --enable-unsafe-extension-debugging`을 주고 CDP `Extensions.loadUnpacked`로 올립니다.
- `--extension=<폴더>`를 주면 그 폴더를 시험합니다. 풀어 놓은 패키지를 시험할 때 씁니다.
- `--store-screenshots`는 스토어용 스크린샷을 수식으로 그린 시험 이미지로 다시 만듭니다 (1280×800, 알파 없는 PNG).
- 스크린샷과 결과 로그는 OS 임시 폴더의 `picmerge-e2e-*`에 남습니다. 경로는 실행 결과에 나옵니다.
- Chrome 위치가 다르면 환경 변수 `CHROME_PATH`로 알려 줍니다.

Chrome Web Store에 올릴 zip은 저장소 최상위에서 만듭니다. `tests/`, `README.md`, 숨김 파일은 들어가지 않습니다.

```
node tool/package_chrome.mjs
```

문구를 고칠 때는 `_locales/`의 14개 폴더(13개 언어, 포르투갈어 2종)를 함께 고칩니다. 키나 `$1` 같은 자리표시가 어긋나면 `tests/i18n.test.mjs`가 잡습니다.

설계는 저장소 최상위 `DESIGN.md`를 봅니다. Chrome 확장에 관한 내용은 §5입니다. 제3자 자산은 `NOTICE.md`에 적혀 있습니다.
